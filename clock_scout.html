Interpretation

  • RTT is measured with performance.now() across a complete HTTPS fetch and response parse.
  • Offset is server UTC − device UTC at the local RTT midpoint. The server time is generated at an undocumented point of the request/response exchange, so a midpoint model introduces potential bias.
  • RTT/2 is a useful scale for network timing ambiguity, not a certified bound on error or server accuracy.
  • Browser request timestamps are not hardware timestamps. Do not extrapolate this probe to Core Motion acquisition timing or GNSS accuracy.
  • Repeat on Wi-Fi and cellular; compare the minimum-RTT subsets and the full CSV. Network caching, proxying, VPNs and thermal/load changes may affect outcomes.

Endpoints: utctime.app, hourora.app, time.now. Their published APIs allow cross-origin HTTPS access. Responses are fetched directly from your device; the page does not upload or store results elsewhere. Each query contacts the chosen provider.
